  WHAT THIS IS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A full-stack, production-grade ecommerce website built for:
  • Premium clothing, accessories, and daily essentials
  • Indian market (Razorpay payments, INR pricing, GST support)
  • Mobile-first, premium design with smooth animations

Tech Stack:
  • Next.js 14 (App Router)         — Framework
  • TypeScript (strict mode)         — Language
  • Tailwind CSS + Framer Motion     — Styling & animations
  • ShadCN UI (via Radix)            — Accessible UI components
  • PostgreSQL + Prisma ORM          — Database
  • JWT (HTTP-only cookies)          — Authentication
  • bcrypt (12 rounds)               — Password hashing
  • OTP via Resend (email)           — Email verification
  • Razorpay                         — Payment gateway
  • Cloudinary                       — Image storage & CDN
  • Zod                              — Input validation everywhere

  FIRST-TIME SETUP (Step by Step)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1 — Clone & Install
  git clone <your-repo>
  cd premiumshop
  npm install    (or: yarn install / pnpm install)

STEP 2 — Set up environment variables
  cp .env.example .env.local
  # Fill in ALL values in .env.local (see REQUIRED SERVICES section below)

STEP 3 — Set up database
  # Make sure PostgreSQL is running and DATABASE_URL is set
  pnpm db:generate     # Generate Prisma client
  pnpm db:migrate      # Run migrations (creates all tables)
  # Or for quick dev: pnpm db:push (skips migration history)

STEP 4 — Create first admin user
  pnpm create-admin
  # Follow the interactive prompts

STEP 5 — Run development server
  pnpm dev
  # App runs at http://localhost:3000

STEP 6 — Build for production
  pnpm build
  pnpm start

  REQUIRED EXTERNAL SERVICES (What You Need to Get)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. PostgreSQL Database
   ─────────────────
   Options: Supabase (free tier), Neon (free tier), Railway, or self-hosted
   URL format: postgresql://USER:PASSWORD@HOST:5432/premiumshop
   Set as: DATABASE_URL

2. Resend (Email — OTP, order confirmations)
   ─────────────────────────────────────────
   Sign up: https://resend.com
   Free tier: 3,000 emails/month
   Required: Verify your sending domain (add DNS records)
   Get key:  Dashboard → API Keys → Create API Key
   Set as: RESEND_API_KEY, RESEND_FROM_EMAIL, RESEND_FROM_NAME
   ⚠️ Important: You MUST verify your sending domain. Otherwise OTP emails won't
      deliver. Go to Resend → Domains → Add Domain → follow DNS instructions.
   ⚠️ For SPF/DKIM/DMARC (Phase 6): Configure in your DNS after adding the domain.

3. Cloudinary (Image Storage)
   ──────────────────────────
   Sign up: https://cloudinary.com (free tier: 25 credits/month)
   Dashboard: https://cloudinary.com/console
   Required: Create an upload preset set to "Signed" mode
   Set as: CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET
            CLOUDINARY_UPLOAD_PRESET

4. Razorpay (Payments)
   ────────────────────
   Sign up: https://razorpay.com
   ⚠️ For testing: Use Test Mode (keys start with rzp_test_)
   ⚠️ For live:    Complete KYC and use Live Mode (keys start with rzp_live_)
   Required:
     • API Keys: Dashboard → Settings → API Keys → Generate Key
     • Webhook:  Dashboard → Settings → Webhooks → Add Webhook
       - URL: https://yourdomain.com/api/webhooks/razorpay
       - Events: payment.captured, payment.failed
       - Secret: Copy the webhook secret
   Set as: RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET
            NEXT_PUBLIC_RAZORPAY_KEY_ID (same as RAZORPAY_KEY_ID, public)

5. Generate Secrets (run these in terminal)
   ─────────────────────────────────────────
   JWT_SECRET (64 chars):
     node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

   JWT_REFRESH_SECRET (64 chars):
     node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

   OTP_PEPPER (32 chars):
     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

   CSRF_SECRET (32 chars):
     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

  DATABASE SCHEMA — ALL TABLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

User              — Customer accounts (email, passwordHash, role, lockout, session version)
RefreshToken      — Hashed refresh tokens (for rotation + revocation)
Otp               — Hashed OTP records (purpose, attempts, expiry)
AuditLog          — All auth events + admin actions (never deleted)
Category          — Product categories (slug, SEO meta, sort order)
Product           — Products (price as Decimal, images[], tags[], soft-delete)
ProductVariant    — Size/Color variants (separate relational table)
WishlistItem      — User wishlists (unique per user+product)
Address           — Delivery addresses (supports multiple, one default)
Cart              — One cart per user
CartItem          — Cart items (unique constraint: cart+product+variant)
Order             — Orders (immutable totals, razorpayOrderId, expiresAt)
OrderStatusHistory — Full audit trail of all status changes
OrderItem         — Line items (snapshot of price at purchase time — immutable)
Transaction       — Payment records (idempotency key, webhookVerified flag)
Review            — Customer reviews (status: PENDING/APPROVED/REJECTED, verifiedPurchase)

All tables have:
  • Proper indexes on all FK columns and query fields
  • created_at / updated_at timestamps
  • Soft-delete (deletedAt) where applicable

  PAYMENT FLOW (How Razorpay Works Here)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. User clicks "Pay ₹XXX" on checkout
2. POST /api/orders/create
   → Server loads cart from DB (never trusts client prices)
   → Calculates subtotal + shipping + 18% GST
   → Creates Razorpay order server-side
   → Creates DB Order with status PAYMENT_PENDING
   → Returns razorpayOrderId + amount to frontend
3. Frontend opens Razorpay checkout modal
4. User completes payment in Razorpay UI
5. Razorpay calls handler with {razorpay_order_id, razorpay_payment_id, razorpay_signature}
6. POST /api/orders/verify
   → Server verifies HMAC-SHA256 signature (NEVER trusts frontend)
   → Updates order to PAID
   → Decrements stock (in DB transaction)
   → Clears cart
   → Sends confirmation email (fire-and-forget)
7. POST /api/webhooks/razorpay (from Razorpay servers)
   → Webhook is the source of truth (idempotent)
   → Updates transaction.webhookVerified = true
   → Advances order to PROCESSING
   → Handles payment.failed events

Price snapshot: OrderItem stores unitPrice at time of purchase (immutable).
If product price changes later, old orders still show correct prices.

Order numbers: Human-friendly format — ORD-2024-000001
Auto-expires:  Pending orders expire after 30 minutes (expiresAt field).

  ADMIN PANEL GUIDE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

URL:      /admin/login
Access:   ADMIN or SUPER_ADMIN role only (verified server-side)
Indexing: Blocked by robots.txt and X-Robots-Tag headers

Pages:
  Dashboard  — Revenue stats, order counts, recent orders
  Products   — Create/view products with image upload (Cloudinary)
  Categories — Create/manage categories
  Orders     — View all orders, update status (strict state machine)
  Reviews    — Moderate pending reviews (Approve / Reject)

Order status machine (only valid transitions allowed):
  PENDING → PAYMENT_PENDING → PAID → PROCESSING → SHIPPED → DELIVERED
  Any status → CANCELLED (before delivery)
  PAID/DELIVERED → REFUND_REQUESTED → REFUNDED

To create first admin:
  pnpm create-admin
  (Follow interactive prompts)

Admin audit log: Every admin action is written to the AuditLog table with
  userId, action, entity, entityId, ipAddress, userAgent, timestamp.

  EMAIL SYSTEM (Resend)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

All emails use inline HTML templates (no React Email dependency — simpler setup).
Templates are defined in: src/lib/resend.ts

Emails sent:
  • OTP verification (registration, login, password reset)
  • Welcome email (after email verified)
  • Order confirmation (with itemized invoice)
  • Order shipped notification

All emails use sendEmailSafe() wrapper — email failures NEVER crash the main flow.

⚠️ Important for production:
  1. Verify your sending domain in Resend dashboard
  2. Add SPF record:  v=spf1 include:_spf.resend.com ~all
  3. Add DKIM record: (Resend provides the exact DNS entry)
  4. Add DMARC record: v=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.com

  IMAGE UPLOAD (Cloudinary)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

All uploads are SIGNED (not unsigned presets) — prevents unauthorized uploads.

Server-side validations:
  • Allowed MIME types: JPEG, PNG, WebP, GIF only
  • Maximum file size: 5MB per file
  • Maximum 8 images per product

Transformations applied automatically:
  • Quality: auto (Cloudinary picks best quality/size ratio)
  • Format: auto (serves WebP/AVIF to browsers that support it)
  • Max dimensions: 1200×1200px (crop: limit — won't upscale)

Admin can upload images when creating products via the admin panel.

Setting up in Cloudinary:
  1. Go to Settings → Upload
  2. Create Upload Preset → Mode: Signed
  3. Copy the preset name → set CLOUDINARY_UPLOAD_PRESET

  REVIEW SYSTEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

• One review per user per product (DB unique constraint)
• All reviews go to PENDING → admin must approve
• Verified Purchase badge: auto-detected (has a DELIVERED order for this product)
• Review body is sanitized with sanitize-html before storage
• Rate limited: 5 reviews per hour per IP
• Aggregate ratings calculated dynamically (only APPROVED reviews)
• Admin review moderation at /admin/reviews
• Suspicious patterns: Track via AuditLog + ReviewStatus controls

  ARCHITECTURE DECISIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Next.js App Router with Route Groups
   (auth) and (store) are route groups — they share layout independently.
   Admin has its own layout with sidebar. No conflicting layouts.

2. Server Components for data fetching, Client Components for interactivity
   Product pages are SSR for SEO. Cart/Checkout are client-side for UX.

3. JWT Access Token (15min) + Refresh Token (7 days) — not session cookies
   Access token in `ps_access` cookie, refresh in `ps_refresh` cookie (path-restricted).
   sessionVersion in JWT is verified against DB on every request.

4. Prices stored as Prisma Decimal, serialized as Number in API responses
   Never store prices as floats. DB Decimal(10,2) prevents rounding errors.

5. Webhook is the source of truth for payment status
   Client verification is a fast path. Webhook confirms and is idempotent.

6. Soft delete (deletedAt) on User and Product
   Orders reference historical products. Products are never hard-deleted.

7. OrderItem snapshots price at purchase time
   unitPrice in OrderItem is set once and never updated. Historic correctness.
